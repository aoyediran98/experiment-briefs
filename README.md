# Experiment Briefs

A static site of pre-registered A/B test briefs. Each brief fixes sample size, run time and success criteria from the funnel numbers first (two-proportion z-test), then the written brief and copy variants are produced around those numbers.

Generated by a Claude skill (`experiment-brief`) that writes the brief, runs `scripts/make_brief.py`, commits, pushes, and returns the live link. Vercel deploys on every push.

## One-time setup (about 10 minutes)

1. **GitHub.** Create a new repository called `experiment-briefs` (public, no README). Then from this folder:
   ```
   git init && git add -A && git commit -m "Experiment brief site"
   git branch -M main
   git remote add origin https://github.com/<your-username>/experiment-briefs.git
   git push -u origin main
   ```
2. **Vercel.** Go to vercel.com → Add New → Project → import `experiment-briefs`. Framework preset: **Other**. Leave build command and output directory empty (it is plain HTML). Deploy. Note the domain, e.g. `experiment-briefs.vercel.app`.
3. **Claude skill.** Save the `experiment-brief` skill in Claude. Open it and replace `<REPO_URL>` and `<SITE_URL>` with your repository URL and Vercel domain.
4. **GitHub access from Claude.** In a Claude session run `gh auth status`. If it is not logged in, run `gh auth login` once and follow the prompts, or connect GitHub as an integration in your Claude settings.

## Everyday use

Ask Claude: "Write an experiment brief: [hypothesis]. Baseline 22%, 18k visitors a week, MDE 8%." The skill clones the repo, writes the brief, runs the script, pushes, and replies with `https://<SITE_URL>/briefs/<slug>.html`. The index page lists every brief.

## Brief structure

Every brief has five parts, and `examples/quiz-goal-ranges.json` shows the full input shape:

1. **The why** — problem or opportunity (what was observed), the hypothesis (change, expected effect, reason), the decision each outcome informs, prior evidence.
2. **What is being tested** — control, variant(s) with the exact change, audience and exclusions, entry point, unit of randomisation.
3. **How it will be judged** — primary metric with numerator, denominator and attribution window; pre-specified success criteria; secondary and guardrail metrics; why this MDE.
4. **Statistics and logistics** — baseline and source, sample size and duration (computed by the script), traffic allocation, stopping rule, pre-registered segments.
5. **Risks and ownership** — risks and dependencies, QA and tracking checks, owners for build, analysis and the call.

## Adding visuals (mockups, screenshots, charts)

Add a `visuals` list to the input JSON. Each entry names a file, a caption and where it belongs:

```json
"visuals": [
  {"path": "visuals/control-goal-step.png", "caption": "Control: current number field", "placement": "control"},
  {"path": "/Users/you/Desktop/variant-b.png", "caption": "Variant B mockup", "placement": "variants"}
]
```

`placement` is one of `problem` (evidence: funnel charts, recordings, survey screenshots), `control`, `variants` (default) or `results` (analysis plan). Paths can be absolute or relative to the JSON file. Accepted types: png, jpg, gif, webp, svg, pdf; files over 5 MB are skipped with a warning, so compress large screenshots first. The script copies each file into `briefs/assets/<slug>/` so it deploys with the page, and renders it as a captioned figure in that section. When using the Claude skill, just attach the images to the chat and say which is which; the skill fills this in.

## Layout

```
index.html            list of briefs (reads briefs/index.json)
style.css             shared styles
templates/brief.html  page template with {{PLACEHOLDERS}}
scripts/make_brief.py computes the stats, renders the page, updates the index
briefs/               generated pages, index.json, assets/<slug>/ visuals
examples/             a sample input.json
```

## Run locally

```
python3 scripts/make_brief.py examples/quiz-goal-ranges.json
python3 -m http.server 8000   # open http://localhost:8000
```
